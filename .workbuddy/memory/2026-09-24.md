## 排查结论：项目没有「模拟盘」（只读审计，未改代码）

用户问「这个项目有模拟盘功能吗」。结论：**没有**成品级 paper trading，四个"近似物"都有硬缺口：

1. `POST /api/strategies/test-run`（`api/strategy.go:547 handleStrategyTestRun`）：真实行情 + 真实候选币 + 可选真实 AI 调用，**不下单**；但权益硬编码 1000.0、持仓固定为空，且**前端零调用**（i18n key `aiTestRun` 无引用），只能手工打 API。
2. 交易所 Testnet：`Exchange.Testnet` 端到端管线存在（store→manager:695/748→AutoTraderConfig→适配器），但**只有 Hyperliquid 实现**（`trader/hyperliquid/trader.go:97-110` 切 `TestnetAPIURL`）；Lighter 有参数但 `trader/auto_trader.go:331-337` 硬编码 `false`；Binance/Bybit/OKX/Bitget/Gate/KuCoin/Aster/Indodax **全部忽略**该标志（OKX `trader/okx/trader.go:232` 显式 `x-simulated-trading: 0` 即拒绝 demo）。**前端没有任何控件能把它置 true**（`setTestnet` 只从已有记录赋值，`HyperliquidWalletConnect.tsx` 五处硬编码 `false`）；i18n `useTestnet` / `testnetDescription` 是死键。
3. `scripts/optimize/{extract,simulate,search}.py`：从 `data/data.db` 抽历史决策 → 换风控/冷却参数重放搜索。**离线参数研究**，注明"决策按录制原样重放"，依赖已有实盘记录，无 UI/API。
4. `deploy/hyperdata/` 的上游 HyperData Terminal 自带 paper-trading engine，但 NOFX 只用其行情端点（`marketdata/providers/hyperdata_client.go` 只调 `/v1/health|orderflow|whales|positions/danger-zone|long-short-ratio|basis|deribit/iv|market`），不调用模拟撮合。

即：设计取向是"真钱 + 真交易所"，护栏靠小额、代码强制风控与熔断，不靠模拟。`DISCLAIMER.md:135` 只是**建议用户自己**去用 paper trading/testnet。

## 排查结论：交易所配置（阶段 4）字段与行为（只读，未改代码）

- **字段矩阵唯一权威**在 `store/visibility.go:5 MissingRequiredExchangeCredentialFields`（不是 `api/handler_trader.go:104 missingExchangeFields`，后者只是它的镜像）：
  - binance/bybit/gate/indodax → api_key + secret_key
  - okx/bitget/kucoin → + passphrase
  - hyperliquid → api_key（agent 私钥）+ hyperliquid_wallet_addr
  - aster → aster_user + aster_signer + aster_private_key
  - lighter → lighter_wallet_addr + lighter_api_key_private_key（注意：**不含** lighter_private_key）
  - 创建白名单 `api/handler_exchange.go:398`：binance/bybit/okx/bitget/hyperliquid/aster/lighter/gate/kucoin/indodax
- **创建即启用**：`store.Create` 与 `store.Update` 都硬写 `enabled: true`（`store/exchange.go:268` / `:299`）。没有"草稿/停用"状态；要停用只能删账户，而有 trader 占用时 `handleDeleteExchange` 会拒绝。
- **更新语义**：`PUT /api/exchanges` body 是 `{exchanges:{<id>:{...}}}`；空字符串字段一律回退为旧值（`handler_exchange.go:249-284`），所以**无法清空**某个凭据，只能删了重建。
- **改配置会重启相关 bot**：`tradersToReload` → `RemoveTrader` → `LoadUserTradersFromStore`（`handler_exchange.go:329-340`）。
- **Hyperliquid 只能钱包连接**：手动填私钥入口已禁用（`web/src/i18n/ui-strings.ts:175 hlw.manualDisabled`）。两次签名 `approveAgent`（agent 名 `NOFX Agent`，`valid_until` 后缀编码 180 天）+ `approveBuilderFee`；builder `0x891dc6f05ad47a3c1a05da55e7a7517971faaf0d`，maxFeeRate `0.05%`，签名链 `0x66eee`。服务端 `POST /api/hyperliquid/submit-exchange` 只放行 approveAgent / approveBuilderFee / usdClassTransfer（`handler_hyperliquid_wallet.go:299-318`），且会校验 builder 地址与费率完全一致；**HTTP 200 + `{"status":"err"}` 会被转为 502**（`:356-371`），避免"报告成功但链上没变"。
- **`GET /api/exchanges/supported` 列了 alpaca/forex/metals，但创建白名单不含它们** —— 这三个只作行情源（`api/handler_klines.go` + `ALPACA_API_KEY`）与 Hyperliquid `xyz:` 的 `hyper_rank_category`，不能作为交易账户创建。
- **"连上了没"的权威来源是 `GET /api/exchanges/account-state`**（真实探测 + 30s 服务端缓存），不是列表页的 `has_api_key`（那只说明"存过"，不代表能连上）。
