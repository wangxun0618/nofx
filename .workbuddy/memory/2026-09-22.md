### 原系统付费依赖地图（重要，回答「是否强制付费」时必查）

结论：**AI 推理可自备 key、完全不用 USDC 钱包；但 Vergex 数据 100% 绑定 Claw402 付费，没有免费通道。**

**① AI 推理 —— 自备 key 是一等公民**
- 原 `api/launch_preflight.go` 的 `checkLaunchAIWallet` 注释：*"Non-claw402 providers pay per API key, so both checks are skipped."*
- 代码守卫：`if model == nil || model.Provider != "claw402" || model.APIKey == ""` → `ai_wallet` / `ai_wallet_funds` 两项置为 **`skipped`**（不是 `failed`）。`ready` 只看 `failed`，故**不阻塞启动**
- 原 `web/src/lib/launch/resolve.ts` 的 `pickTradingModel`：claw402 优先，找不到就回退「任意 `enabled && modelHasCredential`」；`modelHasCredential` 认 `has_api_key || apiKey`（原生）或 `walletAddress`（claw402）

- `NewClient(baseURL, privateKeyHex, logger)` **需要 EVM 私钥**；空则回退 `os.Getenv("CLAW402_WALLET_KEY")`；仍无 → `"claw402 wallet private key not set"`

**③ 关键互斥关系**
`Vergex 的私钥 == claw402 模型的 APIKey`。原 `store/ai_model.go` 的 `ResolveClaw402WalletKey(userID, preferredModelID)`：
1. 若指定 `ai_model_id`，**只有 `Provider == "claw402"` 才取它的 `APIKey` 当钱包私钥**

⇒ **「自备 key」与「用 Vergex 数据」在原系统里互斥**，除非同时再配一个带钱包私钥的 claw402 模型。原默认策略是 `vergex_signal` 看板驱动、强依赖那 5 个接口，所以产品观感才像「必须付费」。

### Vergex 功能全貌（原 `provider/vergex/client.go`，1003 行）

Vergex 不是 UI，而是**通过 Claw402 按次付费的「市场方向信号」数据服务**，核心概念是 direction change（方向变化）：多因子投票出 `bias`（bullish/bearish/neutral）+ `directionScore`。5 个接口：

| 接口 | 关键字段 | 角色 |
| --- | --- | --- |
| `GET /api/v1/vergex/direction-change/leaderboard` | `rank` `bias` `score` `bullishCount` `bearishCount` `neutralCount` `oiRank` `markPrice` `category` `band` `universeSize` `asOf` | **唯一权威**：候选池 + 开仓方向 + 平仓时机 |
| `GET /direction-change/current?symbol=` | `direction` `new_bias` `stable_since_at` `effective_at` `confirmed_at` `reason`（逐因子）`latest_reversal` `readiness{generation,cutoff_at,watermark_at}` | 状态确认（参考） |
| `GET /direction-change/history?symbol=&type=all\|reversal\|non_reversal` | `prev_bias`→`new_bias` `occurred_at` `is_reversal` `reason`/`prev_reason` `next_mark_price` `pagination` | 状态迁移上下文（参考） |
| `GET /cost-liquidation-heatmap?marketType=&symbol=&liqBand=&chain=` | `bins[]{bucketStartPrice,bucketEndPrice,px,longCost,shortCost,longLiq,shortLiq}` `binStep` `costAddrs` `liqAddrs` `cost.state` | 市场结构上下文（参考） |
| `GET /flow-markets?chain=&window=&limit=` | `inflow[]`/`outflow[]{key,marketType,symbol,netFlow,buyNotional,sellNotional,trades,latestPrice}` | **仅前端展示**，不进 AI 决策 |

**原策略语义（`kernel/engine_prompt.go` 的 `buildVergexSystemPrompt` + `vergexHoldRules`）**
决策优先级硬编码：`1. Direction Board 权威 → 2. Current/History 仅状态上下文 → 3. Heatmap 仅结构上下文 → 4. OHLCV 仅价格上下文`。配合的硬规则：
- 空仓 + bullish → 只能 `open_long`，禁 `open_short`；空仓 + bearish 反之
- 已有多头 + 榜单仍 bullish → **无条件 `hold`**（不管盈亏/K线/历史/热力图）
- 平仓**唯一条件**：榜单方向变了 / 变 neutral / 品种从榜单消失
- 保留交易所保护性止损，但**不设固定止盈**（`signal_managed_exit`）
- 同周期禁止反手；无每周期开仓次数上限
- `vergexCustomPromptSection` 会丢弃含 "long only" / "do not short" 的自定义提示（与数据驱动方向冲突）

**AI 侧格式化**：`FormatAnalysisForAI` 把 4 项拼成 markdown；`FormatHeatmapMarkdown` 把 bins 汇总成 Top 10 价格区间表（`| Price zone | Long cost | Short cost | Long liq | Short liq | Main cluster |`），`heatmapZone.MainCluster()` 取四项最大值判定该区间主导类型。

**前端三个面板**：`SignalMatrix.tsx`（榜单→方向矩阵）、`LiquidationMap.tsx`（④→价格分布图）、`FlowMarkets.tsx`（⑤→流入/流出双榜）。

**替代缺口**：成本/强平分布、跨品种资金流、方向变更历史 —— 三项**无替代**；且 `signal_managed_exit` 模式随 `auto_trader_signal_policy.go` 一并删除（现必须设 TP > 0）。

## HyperData Terminal 侧车集成（可插拔 marketdata 层的上游依赖）

集成形态：**HTTP sidecar**，不是代码拷贝。上游是 Python 应用（pyproject 无 `[build-system]`，`pip install -e .`，Python 3.12+，Apache-2.0），不存在可 import 的 Go 包 —— 而这条边界正是「支持后续更新」能成立的原因。

- `marketdata/providers/hyperdata_orderflow.go` / `hyperdata_positioning.go` — 两个 provider，`Enabled = cfg.EnableHyperData`，默认 **false**（需独立进程），实现 `marketdata.ServiceBacked`

### 关键设计决策
- **漂移报告做成 Go 测试，不是第二个探测脚本**。原先有一份 `probe.py`，已删除：它的必需字段表是手写的，会与 fixture 各自漂移；且它把 4xx/5xx 一律当非致命，注释却写「不适用于全市场端点」——**代码没实现该区分**，端点整个消失也会判为 compatible。Go 测试复用同一客户端/fixture/折叠规则 ⇒ 契约只有一份。
- **版本钉是被强制的**：`TestUpstreamPinIsStillMeaningful` 要求 `upstream.env` 的 `HYPERDATA_REVISION`(40 位 SHA)/`HYPERDATA_TESTED_MAJOR`、Go 的 `hyperDataTestedMajor`、`fixtureHealth` 的 `version` 三者主版本一致，只改一半即构建失败。
- **漂移报告的折叠规则**：只有「容器」（非 null 值全为 object/array）才折叠成 `.*`；扁平标量对象**不折叠**（早期版本把全字符串的 health 整块折叠成 `*`，报告直接失效）。标量键动态表（`cumulative_cvd_by_venue`）由 probe 显式声明 `dynamicMaps` —— 因为它与固定字段表 `feeds` 形状无法区分，猜就会要么把掉线的 venue 误报成破坏，要么丢掉被删字段名。已知盲点：单键包裹 map（`{"venues":{...}}`）会被折叠掉键名。
